# Content style guide

Every terminal lesson should:

- Begin with a plain-English takeaway.
- Define unfamiliar terms.
- Use short bullet points.
- Explain why the concept matters.
- Include a tiny diagram when useful.
- Include a command or C compilation prompt when useful.
- Clearly distinguish ISO C, POSIX, Linux-specific behavior, and shell behavior.
- Avoid pretending APUE support helpers such as `err_sys()` are standard C.
- Keep examples original and beginner-friendly.
- Avoid unexplained jargon.
